# План работ: этапы и две независимые линии исполнителей

Источник правды: [`work_plan.json`](work_plan.json). Файл собирается командой `python tools/work_plan.py --plan docs/work_plan.json render`, вручную не правится. Проверка `python tools/work_plan.py --plan docs/work_plan.json check`.

Две линии работают одновременно и не пересекаются по файлам: **A (Сервер)** и **B (Клиент)**. Линия B строит экраны по контрактам из GDD на моках (mock-first), поэтому не ждёт сервер. Директор проектирует, проверяет и сливает в `main`; исполнители работают в своих ветках `v1/<id>-<slug>` и не меняют общие файлы.

## Линия A: Экономическое ядро и каталоги (Исполнитель A)
Сервер, каталог, целочисленные симуляции; без файлов клиента.

Зона файлов: `data/catalog/**`, `server/**`, `tests/server/**`, `tools/sim/**`, `tools/tests/**`

## Линия B: Godot Android и UI (Исполнитель B)
Только клиент Godot, макеты директора читать, API на моках.

Зона файлов: `client/**`, `tests/client/**`

## Правила

1. Выдавать только пакеты со статусом «можно выдавать» (все зависимости готовы): `python tools/work_plan.py next`.
2. Текст задания генерируется: `python tools/work_plan.py prompt A1`.
3. Исполнитель не меняет общие файлы директора: `README.md`, `docs/PROGRESS.md`, `docs/work_plan.json`, `docs/WORK_PLAN.md`, `docs/gdd/**`, `docs/AI_RULES.md`, `docs/PORTAL_PROTOCOL.md`, `tools/work_plan.py`, `.github/workflows/**`.
4. Новые флаги серверных механик выключены по умолчанию; включает только владелец.
5. Слияние в `main` делает директор после пробного слияния, полного набора серверных тестов на PostgreSQL и всех клиентских проверок.

## Доска задач (страница для владельца)
